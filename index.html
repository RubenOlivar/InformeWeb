Despliegue de WordPress con Docker y MariaDB

Documentación del despliegue y configuración de un servidor web WordPress integrado con una base de datos MariaDB, usando Docker y WSL2 en un entorno local.

bumper@PCRuben:~/proyecto-wordpress$ docker compose up -d
[+] Running 4/4
✔ Container proyecto-wordpress-db-1 Started
✔ Container proyecto-wordpress-wordpress-1 Started

01Objetivo

Implementar un servidor web WordPress utilizando Docker sobre WSL2, integrando una base de datos MariaDB y configurando la comunicación entre ambos servicios mediante Docker Compose. Finalmente, se verifica el funcionamiento del sitio desde un navegador web.

El informe recorre las siguientes etapas:

  • Instalación de Docker sobre WSL2
  • Despliegue del servidor web WordPress
  • Definición del archivo docker-compose.yml
  • Despliegue de la base de datos MariaDB
  • Arquitectura y comunicación entre servicios
  • Personalización visual con CSS
  • Verificación de la base de datos y evidencia de funcionamiento

02Instalación de Docker sobre WSL2

Se instaló WSL2 (Windows Subsystem for Linux versión 2) con la distribución Ubuntu, y posteriormente Docker Desktop configurado para usar el motor basado en WSL2. La instalación se verificó con los comandos wsl --version y wsl -l -v, confirmando que Ubuntu corre en versión 2.

Luego, en Docker Desktop se activó la integración con la distribución Ubuntu desde Settings → Resources → WSL Integration, permitiendo ejecutar comandos de Docker directamente desde la terminal de Linux. Adicionalmente, se observa la distribución docker-desktop, creada automáticamente por Docker Desktop como parte de su integración con WSL2.

03Servidor web WordPress

El servidor web se desplegó utilizando la imagen oficial wordpress:latest, descargada automáticamente desde Docker Hub. La configuración se definió en un archivo docker-compose.yml, junto con el servicio de base de datos. El contenedor quedó expuesto en el puerto 8080 del equipo local, accesible desde el navegador en http://localhost:8080.

04Archivo docker-compose.yml

A continuación se presenta el archivo docker-compose.yml utilizado para definir y orquestar los dos servicios del proyecto. En él se especifican las imágenes de Docker Hub, las variables de entorno, los puertos expuestos y los volúmenes usados para la persistencia de datos.

services:
  db:
    image: mariadb:latest
    container_name: proyecto-wordpress-db-1
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: wppassword
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wpuser
      MYSQL_PASSWORD: wppassword
    volumes:
      - db_data:/var/lib/mysql

  wordpress:
    image: wordpress:latest
    container_name: proyecto-wordpress-wordpress-1
    restart: always
    depends_on:
      - db
    ports:
      - "8080:80"
    environment:
      WORDPRESS_DB_HOST: db:3306
      WORDPRESS_DB_NAME: wordpress
      WORDPRESS_DB_USER: wpuser
      WORDPRESS_DB_PASSWORD: wppassword
    volumes:
      - wp_data:/var/www/html

volumes:
  wp_data:
  db_data:

05Base de datos MariaDB

La base de datos se desplegó como un segundo contenedor, utilizando la imagen mariadb:latest obtenida también desde Docker Hub. Se configuró con un usuario, contraseña y nombre de base de datos específicos para WordPress.

El contenedor de WordPress se conecta a este servicio a través de la red interna creada automáticamente por Docker Compose, usando la variable WORDPRESS_DB_HOST: db:3306. MariaDB es un motor de base de datos relacional compatible con MySQL y basado en el lenguaje SQL.

06Arquitectura del proyecto

El proyecto está compuesto por dos contenedores independientes que se comunican mediante una red interna creada automáticamente por Docker Compose. El navegador realiza peticiones al puerto 8080 del equipo local, que Docker redirige al contenedor de WordPress (puerto 80 interno).

Dentro de este contenedor, quien recibe y procesa dichas peticiones es Apache, el servidor web incluido en la imagen oficial wordpress:latest, que trabaja junto con PHP para ejecutar el código de WordPress. WordPress, a su vez, se conecta al contenedor de la base de datos a través del nombre de servicio db en el puerto 3306, sin necesidad de exponer ese puerto al exterior, lo que mejora la seguridad del entorno.

  1. El navegador accede a WordPress mediante localhost:8080, que se mapea al puerto 80 del contenedor.
  2. WordPress consulta a MariaDB mediante TCP en el puerto 3306, usando el nombre de servicio db dentro de la red interna.
  3. MariaDB devuelve los datos solicitados por la consulta SQL.
  4. WordPress genera la respuesta HTML y esta retorna al navegador.

07Personalización visual

Se implementó un conjunto de estilos CSS personalizados para mejorar la presentación y organización del informe en WordPress. Se configuraron colores, tamaños y estilos para títulos, subtítulos y párrafos, incluyendo una numeración automática para las secciones. También se añadieron efectos visuales a las imágenes, como bordes redondeados, sombras y animaciones al pasar el cursor.

Además, se mejoró la presentación de tablas, listas, enlaces, bloques de código y citas, utilizando una apariencia más organizada y profesional. Se configuraron botones y elementos de la cabecera y el pie de página para mantener una identidad visual uniforme.

Finalmente, se incluyeron reglas específicas para impresión y generación de PDF, eliminando elementos innecesarios y ajustando tamaños y colores, junto con configuraciones responsive para garantizar una correcta visualización en dispositivos móviles.

08Verificación de la base de datos

Para comprobar que MariaDB almacena correctamente los datos generados por WordPress, se accedió directamente al contenedor de la base de datos mediante el cliente mariadb, y se consultó la tabla wp_posts.

# acceso al cliente de MariaDB dentro del contenedor
docker compose exec db mariadb -u wpuser -p wordpress

# consulta de las páginas registradas
SELECT ID, post_title, post_status FROM wp_posts
WHERE post_type='page';

El resultado confirma que la página del informe está registrada con estado publish, validando la conexión funcional entre ambos contenedores.

09Evidencia de funcionamiento

Accediendo desde el navegador a http://localhost:8080 se completó el asistente de instalación de WordPress. El panel de administración (wp-admin) confirma que el servidor web y la base de datos están correctamente conectados y operativos.
